# Суфлёр для музыкантов

Десктопная программа, которая показывает текст песни с аккордами и **сама листает строки,
слушая голос**. Музыкант заранее набивает очередь песен, а во время выступления видит на
экране только небольшое окно текста вокруг текущей строки.

Распознавание речи полностью офлайн — через [vosk](https://alphacephei.com/vosk/).
Интернет нужен только для поиска текстов и однократного скачивания моделей.

---

## Возможности

- Очередь песен: добавление, удаление, изменение порядка (перетаскиванием или кнопками).
- Автоматический поиск текста с аккордами; если не нашлось — ручная вставка,
  загрузка файла `.txt` / `.pro` (ChordPro) или прямая ссылка на подбор.
- Экран исполнения: окно из 5 строк — две предыдущие и две следующие приглушены,
  текущая крупная, аккорды нарисованы над нужными словами.
- Автопрокрутка по голосу с нечётким сравнением слов (русский и английский).
- Полное ручное управление с клавиатуры — на случай, если микрофон подводит.
- Индикатор уровня микрофона и лог распознанных слов для отладки.

## Установка

Нужен **Python 3.11 или новее** (проверено на 3.12).

```bash
cd text_for_songs

# Виртуальное окружение (пример для macOS с Homebrew-питоном)
python3.12 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

### Про версию vosk

В `requirements.txt` версия зафиксирована: `vosk==0.3.44`. Это не прихоть — последняя
версия на PyPI (0.3.45) собрана без единого колеса под macOS, и `pip install vosk`
на Apple Silicon просто падает. 0.3.44 — последняя версия с `macosx_10_6_universal2`.

### Про PortAudio

Отдельно ставить его **не нужно**: пакет `sounddevice` несёт собственную сборку
PortAudio внутри. `brew install portaudio` не требуется.

## Модели распознавания

Модели не входят в репозиторий — они весят десятки мегабайт.

**Проще всего**: запустить программу и начать исполнение. Если модель для языка песни
не найдена, приложение предложит скачать её само и покажет прогресс.

**Вручную** — скачать и распаковать в папку `models/` рядом с `main.py`:

| Язык | Модель | Размер | Ссылка |
|---|---|---|---|
| Русский | `vosk-model-small-ru-0.22` | ~45 МБ | https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip |
| Английский | `vosk-model-small-en-us-0.15` | ~40 МБ | https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip |

После распаковки структура должна быть такой:

```
text_for_songs/
└── models/
    ├── vosk-model-small-ru-0.22/
    │   ├── am/
    │   ├── conf/
    │   ├── graph/
    │   └── ivector/
    └── vosk-model-small-en-us-0.15/
        └── ...
```

Язык песни определяется автоматически по её тексту, и поднимается нужная модель.
Полный список моделей — на https://alphacephei.com/vosk/models.

> Большие модели (например, `vosk-model-ru-0.42` на 1.8 ГБ) для суфлёра избыточны:
> они точнее, но заметно медленнее в реальном времени.

## Запуск

```bash
source .venv/bin/activate
python main.py
```

**На macOS при первом запуске система спросит разрешение на микрофон.** Если случайно
отказать, программа не сможет ничего услышать — при этом ошибки не будет, просто
наступит тишина. Приложение это замечает и подсказывает, куда идти:
*Системные настройки → Конфиденциальность и безопасность → Микрофон*.

## Как пользоваться

### 1. Соберите очередь

Введите исполнителя и название **одной строкой** и нажмите **«Найти и добавить»».
Программа покажет список найденного — обычно там несколько вариантов: оригинал,
каверы, переводы, — и вы выбираете нужный. Статус загрузки виден прямо в списке:
`ищу текст…`, `готово, строк: 24` или причина неудачи.

Порядок песен меняется перетаскиванием или кнопками **↑ Выше** / **↓ Ниже**.

Если текст не нашёлся, есть три запасных пути:

- **«Задать текст…»** (или двойной клик по пункту) — вставить текст руками;
- **«Вставить текст…»** — добавить песню сразу с текстом;
- **«По ссылке…»** — дать прямую ссылку на страницу с подбором.

Формат вставляемого текста — обычный аккордовый лист:

```
Am        C         G
здесь идёт первая строка текста

Am           C
здесь вторая строка
```

Ведущие пробелы важны — именно они говорят, над каким слогом стоит аккорд.
ChordPro (`[Am]аккорд прямо [C]в строке`) тоже понимается, формат определяется сам.

### 2. Выступайте

Нажмите **«Начать»**. Программа слушает микрофон, сравнивает распознанные слова
с текущей строкой и, когда совпадение уверенное, сдвигает окно вперёд.

**Служебные строки уходят сами.** Заголовки блоков и схемы боя спеть нельзя, и голос
их никогда не сдвинет — на них суфлёр завис бы навсегда. Поэтому они пропускаются
по таймеру: если в строке указана длительность («Вступление 8 сек», «Проигрыш x2»),
берётся она, иначе полсекунды — только чтобы вы успели заметить блок. И длительность,
и само поведение настраиваются.

Важная тонкость: сопоставление с голосом идёт только по строкам со словами, но
**останавливается суфлёр и на служебных**. Иначе при пении заголовки просто
проскакивали бы молча, и вы бы не видели, что начался припев.

Заголовок опознаётся тремя способами: по названию блока («Припев», «Pre-Chorus»,
«Instrumental» — в любом написании), по квадратным скобкам и просто **по двоеточию
в конце короткой строки**. Последнее покрывает всё остальное: «Соло гитары:», «Кода:».
Длинная фраза с двоеточием заголовком не считается — это уже часть текста.

**Строка едет плавно.** Мгновенный скачок на сцене читается как рывок: глаз теряет
место и заново ищет текущую строку. Строка трогается почти незаметно, разгоняется
к середине пути и долго успокаивается в конце — движение задано кубической кривой,
как в плеерах с синхронным текстом.

Анимируется **весь переход**, а не только сдвиг: положение, размер и яркость каждой
строки берутся промежуточными между «как было» и «как станет». Это принципиально —
если двигать одну позицию, размер всё равно меняется скачком, соседняя строка
мгновенно становится крупной, и глаз читает это как рывок, какую кривую ни подбирай.
Текст рисуется с субпиксельной точностью, иначе буквы прыгали бы по целым пикселям.

**Длинные строки не обрезаются.** Сначала шрифт слегка ужимается — строка на пару слов
длиннее нормы читается лучше чуть мельче, чем разорванной пополам. Если и при
минимальном размере (72 % от заданного) не помещается, строка переносится: дальше
уменьшать значит сделать текст нечитаемым с расстояния. Аккорды при переносе
распределяются по кускам, а место под них резервируется только там, где они есть.

Перенос — только для показа: на голосовую прокрутку он не влияет, строка песни
остаётся одной строкой.

Длительность настраивается («Плавность прокрутки»), от 0 до 800 мс. Ноль полностью
выключает анимацию — на быстрых песнях так может быть удобнее.

| Клавиша | Действие |
|---|---|
| `Пробел`, `→`, `↓` | следующая строка |
| `←`, `↑` | предыдущая строка |
| `N` | следующая песня |
| `F` | полноэкранный режим |
| `Esc` | выйти из полного экрана, затем вернуться к очереди |

После последней строки песни автоматически начинается следующая; когда очередь
пройдена — возврат к экрану ввода.

### 3. Настройте под себя

**«Настройки…»** на экране очереди:

- **слушать только слова текущей песни** — главный рычаг точности, включён по умолчанию
  (см. ниже);
- **порог совпадения** — какая доля значимых слов строки должна быть распознана
  (по умолчанию 60 %). Ниже порог — охотнее листает, но чаще ошибается;
- **пропуск служебных строк** и сколько держать строку без указанной длительности;
- **плавность прокрутки** — длительность доезда строки или полное её отключение;
- **микрофон** — выбор устройства;
- **размер шрифта** и сколько строк показывать до и после текущей;
- **голосовая прокрутка** — можно выключить и листать только руками;
- **показывать распознанные слова** — маленький лог для отладки.

### Два движка распознавания

| | vosk | системный macOS |
|---|---|---|
| Где работает | везде | только macOS и только из `.app` |
| Что качать | модели 45–128 МБ | ничего, уже в системе |
| Ошибки: русский с гитарой | 21 % | **4 %** |
| Ошибки: английский с акцентом | 16 % | **0 %** |
| Ограничение словаря | жёсткая грамматика | подсказка контекстом |

Цифры — с замера на одном и том же аудио: семь фраз синтезированной речи,
поверх которых наложен гитарный перебор. Материал искусственный, поэтому на живом
пении разрыв наверняка окажется скромнее, но он слишком велик, чтобы быть
случайностью выборки.

По умолчанию стоит vosk: он работает при любом способе запуска. Системный движок
выбирается в настройках и требует сборки `.app` (см. ниже). Если он окажется
недоступен — нет разрешения, запуск не из бандла, нет нужного языка — суфлёр молча
вернётся к vosk и напишет об этом в отладочной строке.

### Сборка .app для системного распознавания

```bash
python build_app.py
open Суфлёр.app
```

Приложение обязано принадлежать бандлу с объявленным
`NSSpeechRecognitionUsageDescription` — иначе macOS убивает процесс при первом
обращении к распознаванию, даже не показав диалога. Это требование системы, обойти
его настройкой нельзя.

Внутри бандла лежит не копия питона, а запускающий скрипт, зовущий интерпретатор
из `.venv`. Поэтому после правок кода пересобирать бандл не нужно.

При первом запуске macOS спросит доступ к микрофону и к распознаванию речи.

### Про точность распознавания

Точность собирается из четырёх независимых средств — каждое включается отдельно.

**1. Ограничение словаря.** Самое сильное. Суфлёр заранее знает, что человек собирается
петь, поэтому распознавателю передаётся словарь именно этой песни, а не весь язык. На
практике это десятки слов вместо десятков тысяч: у типичной песни выходит 60–180
уникальных слов. Слова, которых нет в словаре самой модели, она молча пропускает,
а если грамматику принять не удалось — распознавание продолжается по общему словарю.

Отдельная тонкость: в словарь слова идут **с буквой «ё»**, хотя при сравнении она
сводится к «е». Русская модель хранит слова именно с «ё» и молча выбрасывает формы,
где вместо неё стоит «е», — иначе заметная часть словаря песни пропадала бы впустую.

**2. Модель покрупнее** (настройка «Модель распознавания покрупнее»). Маленькая
английская модель рассчитана на произношение носителя и заметно спотыкается на акценте.
`vosk-model-en-us-0.22-lgraph` — 125 МБ вместо 39 и всё ещё поддерживает ограничение
словаря, без которого смысл терялся бы. Для русского такой пары нет: следующая
по качеству модель весит 1.8 ГБ и для реального времени тяжела.

**3. Сравнение на слух.** Тем, кто поёт по-английски без родного произношения, мешает
прежде всего межзубный звук: `think` звучит как «синк», `nothing` — как «носинг».
Побуквенное сравнение такие слова не узнаёт, поэтому длинные английские слова
дополнительно сверяются по «звуковому скелету» — согласным без гласных, с поправкой
на типичные подмены. Короткие слова так не сравниваются: у них скелеты слишком часто
совпадают у совершенно разных слов.

**4. Чистка звука** (настройка «Чистить звук перед распознаванием») — см. ниже.

### Про шум от инструмента

Когда человек играет на гитаре и поёт в один микрофон, полностью отделить голос от
инструмента **нельзя** — это задача разделения источников, её решают нейросети вроде
Demucs, и в реальном времени на процессоре они не работают. Честный потолок здесь такой:

- **срез низа** — самые громкие струны лежат ниже голоса, и именно они забивают вход;
  разборчивость речи держится на формантах выше 300 Гц, так что голос почти не страдает.
  На синтетической смеси «гитара + голос» гитарного низа становится вдвое меньше
  относительно речевого диапазона;
- **подавление пауз** — когда голос смолк, а гитара звучит, блок глушится, и
  распознаватель не выдумывает слова из перебора.

Своего выравнивания громкости здесь намеренно нет: vosk нормализует признаки сам,
а вторая нормализация поверх возвращала бы срезанному низу прежний уровень.

Если гитара всё равно перебивает — сильнее всего помогает не софт, а расположение
микрофона: ближе ко рту и дальше от деки.

### Про алгоритм автопрокрутки

Самая содержательная часть — `matcher.py`. Несколько решений, которые стоит пояснить:

**Порог сравнения зависит от длины слова.** Единый порог не работает: пары
«тебя / тебе» и «день / тень» одинаково близки формально, но в первом случае это одно
слово с испорченным окончанием, а во втором — разные слова. Поэтому слова до трёх букв
сверяются точно, а длинные — нечётко.

**Jaro-Winkler вместо обычного расстояния.** Он даёт бонус за совпадающее начало слова,
а распознавание пения портит именно окончания.

**Наибольшая общая подпоследовательность, а не «доля общих слов».** Метрики, которые
игнорируют порядок, дали бы почти сто процентов на строке, спетой задом наперёд.

**Кандидаты берутся только из окна вокруг текущей строки.** Это же решает проблему
припевов: одинаковые строки из других куплетов просто не попадают в рассмотрение,
поэтому программа не прыгает в конец песни на первом же повторе.

**Суфлёр умеет догонять.** Распознаватель нередко прозёвывает строку целиком:
человек уже поёт следующую, а окно стоит на месте. Поэтому кандидатами считаются
не только текущая строка, но и две следующие — если узнаётся одна из них, окно
переезжает сразу туда.

У требования к такому перескоку есть потолок. Надбавка за дальность без него
быстро уводила требование выше единицы, то есть за пределы возможного: при пороге
75 % догнать человека было нельзя в принципе, сколько бы он ни пел вперёд.

Заглядывать дальше двух строк нельзя — на замерах повтор припева начинал утаскивать
в конец песни.

**Прыжок вперёд опирается только на отличающиеся слова.** Приём, когда конец одной
строки повторяется в начале следующей, встречается сплошь и рядом. Если засчитывать
общие слова, вторая строка «узнаётся» ещё до того, как её начали петь: суфлёр уходит
на неё, потом засчитывает те же слова ещё раз — и строка пропадает, хотя её не пели.
Поэтому при оценке прыжка слова, общие с текущей строкой, не считаются вовсе.

**Защита от дребезга.** Промежуточные гипотезы распознавателя приходят много раз подряд
и каждый раз с начала фразы. Поэтому уже сработавшие слова помечаются использованными,
а между переходами выдерживается небольшая пауза.

**Короткой строке всегда прощается одно слово.** Заданный процент на коротких строках
превращается в требование идеала: при пороге 75 % строка из трёх слов требует все три,
потому что округление съедает весь запас. Одна осечка распознавателя — и такая строка
не сработает никогда. Поэтому порог для строки не бывает выше `(N-1)/N`; на длинных
строках это ничего не меняет.

**Служебные слова отбрасываются, только пока они в меньшинстве.** Строки, собранные
почти целиком из местоимений и предлогов, встречаются постоянно, и там отсев выкашивает
почти всё: от восьми слов остаётся два коротких. Если значимых слов меньше трёх или
меньше 40 % строки, сверяемся по всем словам.

## Источники текстов

Источник меняется реализацией `LyricsProvider`. Сейчас в цепочке:

| Источник | Поиск по названию | Загрузка по ссылке |
|---|---|---|
| MyChords | **да** — основной путь | да |
| Ultimate Guitar | только с выключенным robots-гейтом | да |
| AmDm | только с выключенным robots-гейтом | да |
| Файл `.txt` / `.pro` / `.cho` | — | — |
| Ручная вставка | — | — |

Найденные песни кэшируются в `cache/`, поэтому повторный запуск не ходит в сеть.

**Про robots.txt.** Перед автоматическим запросом программа спрашивает разрешения
у самого сайта и по умолчанию его уважает — эту проверку можно отключить в настройках.
Отсюда разница между источниками:

- **mychords.net** ничего из нужного не запрещает, поэтому поиск по названию работает
  из коробки. Обычная страница выдачи рисуется скриптом и по GET-запросу не приходит,
  так что программа спрашивает тот же эндпоинт подсказок, которым пользуется сам сайт, —
  он отдаёт готовый JSON со ссылками на подборы;
- **Ultimate Guitar** закрывает `/search.php` для всех роботов, поэтому поиск там
  включается только вместе с отключением robots-гейта. Страницы табов не запрещены,
  и загрузка по прямой ссылке работает всегда;
- **amdm.ru** закрывает `/search` в блоке `User-agent: *` — то есть для любых
  автоматических клиентов, а не только для поисковых роботов. Поэтому поиск по нему
  по умолчанию выключен и включается только вместе со снятием галочки «Уважать
  robots.txt»: решение отступить от этого принимаете вы, а не программа молча.
  Загрузка по прямой ссылке работает всегда — страницы подборов не запрещены.

Именно на amdm.ru у песни чаще всего лежит несколько подборов сразу, поэтому там
поиск особенно полезен: по одному запросу видно все версии одной песни.

### Несколько версий одной песни

У популярных песен лежит по несколько подборов: с табулатурой и с аккордовой сеткой,
в разных тональностях, упрощённые. Кнопка **«Другая версия…»** ищет их двумя путями
сразу — среди ссылок на соседние версии прямо со страницы подбора и поиском по названию.

Если в текущей версии нет аккордов, список очереди пишет об этом прямо:

```
1.  Weezer — Buddy Holly   — готово, строк: 21, без аккордов (есть другие версии: 1)
```

Автопоиск покрывает не все сайты: на amdm.ru он закрыт robots.txt, хотя версий там
может быть несколько. Поэтому в списке версий всегда есть пункт **«Вставить ссылку
на другой подбор…»** — прямая ссылка работает всегда.

### Два типа страниц на amdm.ru

Разбор проверен на сохранённых страницах, и там встречаются страницы двух видов:

- **аккордовый подбор** — сетка аккордов над словами, разбирается полностью;
- **табулатура** — вместо аккордов ASCII-схема перебора по струнам (`e|---3---`).
  Аккордов на такой странице может не быть вовсе.

Табулатура разбирается отдельно и показывается на экране исполнения в правой панели,
моноширинным шрифтом — в общий поток строк она не встраивается, потому что спеть её
нельзя и голосовая прокрутка по ней не идёт.

### Особенность разбора mychords.net

У страницы есть кнопка «скрыть аккорды», и ради неё сайт держит в разметке сразу
**две копии** песни: строфы вместе с аккордами и отдельно голый текст. Если разбирать
контейнер целиком, каждая строка задваивается — в одном подборе строка повторялась
двенадцать раз, что полностью ломает автопрокрутку. Поэтому парсер берёт только строфы
с аккордами (`div.pline` и `div.single-line`).

## Известные ограничения и что можно улучшить

**Ограничения**

- **Распознавание пения заметно хуже распознавания речи.** Долгие распевы, мелизматика
  и громкий аккомпанемент в одном помещении сильно снижают точность. Автопрокрутка —
  это помощь, а не замена ручному управлению; клавиатура всегда должна быть под рукой.
- **Инструментальные проигрыши программа не отслеживает** — во время них голоса нет,
  поэтому окно стоит на месте. Строки без слов проскакиваются только при переходе.
- **vosk на macOS зафиксирован на версии 0.3.44** — свежие версии апстрим под macOS
  не собирает.
- **Табулатура показывается, но не транспонируется и не прокручивается голосом** —
  она сбоку и меняется вместе с блоком песни.
- **Поиск находит не всё.** Эндпоинт подсказок mychords.net отдаёт пять вариантов,
  и если нужной песни среди них нет, программа честно скажет «текст не найден»
  вместо того, чтобы подсунуть похожую. Совсем непохожие совпадения отбрасываются.
- **Парсинг чужих сайтов ломается при смене их вёрстки.** Устойчивый путь — файлы и
  ручной ввод.
- Тексты песен защищены авторским правом: программа рассчитана на личное использование,
  кэш хранится только локально.

**Что можно улучшить**

- **Сужать словарь до ближайших строк.** Сейчас распознавателю передаются слова всей
  песни; можно оставлять только слова окна вокруг текущей строки и перестраивать
  грамматику на ходу — точность вырастет ещё, но потребуется аккуратно пересоздавать
  распознаватель, не теряя звук.
- **Плавная анимация прокрутки** вместо мгновенной перерисовки.
- **Учёт темпа**: если известна длительность строк, можно подстраховывать голос временем.
- **Транспонирование аккордов** и поддержка каподастра прямо на экране.
- **Автопрокрутка длинных строк** по горизонтали, если строка не помещается по ширине.
- **Экспорт очереди** в файл, чтобы переносить сет-лист между машинами.
- **Ножная педаль** (MIDI или Bluetooth-пульт) как альтернатива клавиатуре.
